# link

按 `appType` 把每个 app 的 controllers 聚合成单个函数。

## 决策表

| appType | 输出文件 | 函数名 | import 前缀 | 备注 |
|---|---|---|---|---|
| `b2b-api` | `src/modules/index.ts` | `applyAllModules` | `.` | health 单独 export |
| `web` | `src/server/index.ts` | `applyAllControllers` | `./modules` | 聚合在 `src/server/`,modules 下一层 |
| `b2b-admin` | — | — | — | 跳过 |
| `frontend` | — | — | — | 跳过 |

## 扫描规则

`discoverControllers(modulesDir, importPrefix)`：
- 递归扫 `modules/` 下**一级子目录**，跳过 `_` 开头（`_health` / `_dev` 视为非真模块）和 `SKIP_DIRS`。
- 必须存在 `<name>/<name>.controller.ts` 才算真模块。
- AST 提取 `export const <name> = new Elysia(...)` 里的变量名（要求 camelCase，否则 warn）。
- import 路径：`${importPrefix}/${<name>}/${<name>}.controller`（去掉 `.ts` 后缀，符合 ESM）。

## 重名处理

`disambiguateNames(files)`：
- 同名变量（如多个 `userController`）按父目录名前缀化：`admin_userController`。
- 顶层同名无父目录的保留原名（throw-style 不会发生，但日志 warn 提醒）。

## b2b-api 的 health 单独 export

`b2b-api` 习惯把 `health.controller.ts` 单独 `export { healthController }`，供 `server.ts` 在启动时 `.use(healthController)` 做探活。`link` 会**额外 export** health，但不在 `applyAllModules` 里 `.use(healthController)`（避免健康检查被业务权限框架影响）。

## 输出示例（b2b-api）

```ts
// Auto-generated by `api-gen link` — b2b-api modules aggregator. Do not edit manually.
// Run `api-gen link` to refresh.
import type { Elysia } from "elysia";

export { healthController } from "./health/health.controller";

import { customerController } from "./customer/customer.controller";
import { siteController } from "./site/site.controller";

export function applyAllModules(app: Elysia) {
  return app
    .use(customerController)
    .use(siteController);
}
```

## 手动维护保护

`barrel` / `link` 共用同一规则：**已存在但首行无 `// Auto-generated` 标记的文件视为手动维护，跳过不覆盖**。如果改了 link 输出的内容要重新生成，先删除文件再跑命令（或在文件首行加 marker 强制覆盖）。
