# gen-tbschema

从 `*.dbschema.ts` + `tbschema/raw/<name>.dbschema.raw.ts` 派生 `tbschema/<name>.tbschema.ts` 骨架（用 `XxxRawInsert/Select/Update` 拼装）。

## 流程

1. 读 `.vscode/api-gen.json`，取 `common.dbschemaFiles` 和 `common.tbschemaRoot`。
2. 对每个 dbschema 文件 AST 提取 `pgTable` 导出变量（同 `raw`）。
3. **依赖检查**：`tbschema/raw/<kebab>.dbschema.raw.ts` 必须存在；不存在则跳过该表并 warn 提示先跑 `api-gen raw`。
4. 生成 `<kebab>.tbschema.ts` 骨架（含 `Response/Create/Update/Patch/ListQuery/ListResponse` 6 个键 + `XxxContract = InferDTO<typeof XxxTBSchema>` 类型）。
5. 写到 `common.tbschemaRoot/<kebab>.tbschema.ts`。

## 骨架内容

```ts
/** biome-ignore-all lint/style/useNamingConvention: 契约文件固定约束 */
// Auto-generated by api-gen gen-tbschema — do not edit manually.
import { Type as t } from "typebox";
import { type InferDTO, PaginationParamTBSchema, SortParamTBSchema } from "../utils";
import { SiteRawInsert, SiteRawSelect, SiteRawUpdate } from "./raw";

export const SiteTBSchema = {
  Response: t.Object({ ...SiteRawSelect.properties }),
  Create: t.Object({ ...t.Omit(SiteRawInsert, ["id", "createdAt", "updatedAt"]).properties }),
  Update: t.Partial(t.Object({ ...t.Omit(SiteRawInsert, ["id", "createdAt", "updatedAt"]).properties })),
  Patch: t.Partial(t.Object({ ...t.Omit(SiteRawInsert, ["id", "createdAt", "updatedAt"]).properties })),
  ListQuery: t.Object({
    ...t.Partial(SiteRawInsert).properties,
    ...PaginationParamTBSchema.properties,
    ...SortParamTBSchema.properties,
  }),
  ListResponse: t.Object({
    data: t.Array(t.Object({ ...SiteRawSelect.properties })),
    total: t.Number(),
  }),
} as const;

export type SiteContract = InferDTO<typeof SiteTBSchema>;
```

## 保护机制

- **已存在无 marker**：跳过（视为手动维护，warn）。
- **已存在有 marker 且无 `--force`**：跳过（视为已生成的骨架，避免无意义覆盖）。
- **raw 缺失**：跳过该表（warn 提示依赖 `api-gen raw`）。
- **`--force`**：覆盖已有骨架（marker + 业务字段都重置回初始状态）。

## 何时用 `--force`

骨架里用了 `XxxRawInsert/Select` 的 `properties` 展开，业务字段是"raw 全集"。如果你手动精简过 `Create` / `Update` 的字段，再次跑 `gen-tbschema` 会**还原成全字段**。这种情况用 `--force` 不会更好（还是覆盖），正确的做法是**不跑 `gen-tbschema`，手工改**已经存在的骨架。
