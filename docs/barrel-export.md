# Barrel Export — 桶导出规范

## 什么是 Barrel Export

Barrel（桶）是 TypeScript 社区对**通过 `index.ts` 集中转发目录内所有导出**的模式称呼。核心思路：

```
utils/pagination/
├── page.ts          ← 叶子文件，写真实代码
└── index.ts         ← barrel，自动转发所有导出
```

## 为什么需要

| 问题 | 方案 |
|------|------|
| 使用者要记深层 import 路径 | 统一从组级 `index.ts` 导入 |
| `export *` 让 Tree Shaker 不敢删 | 全量**具名导出**，精准 tree-shaking |
| 值/类型混在一起，类型无法擦除 | `export {}` / `export type {}` 分离 |
| 手动维护 index 容易漏 | `api-gen barrel` 自动生成 |

## 目录规范

```
contract/
├── utils/
│   ├── pagination/
│   │   ├── page.ts          ← 叶子：真实代码
│   │   └── index.ts         ← barrel：CLI 生成
│   ├── sort/
│   │   ├── sort-helper.ts
│   │   └── index.ts
│   ├── search/
│   │   ├── filter.ts
│   │   └── index.ts
│   └── index.ts             ← 组级 barrel：CLI 生成
├── drizzle/
│   └── index.ts
├── typebox/
│   └── index.ts
├── constants/
│   └── index.ts
└── query-types.model.ts      ← 手动维护
```

## 配置

在 `.vscode/api-gen.json` 中，`exportIndex` 是 `api-gen init` 自动生成的：

```json
{
  "exportIndex": {
    "includes": ["utils"],
    "constants": ["packages/contract/src/constants"],
    "hooks": ["packages/contract/src/hooks"],
    "utils": ["packages/contract/src/utils"]
  }
}
```

- **`includes`** — 要处理的组名清单，只有在这里的组才会被执行
- **其余 key** — 组名 → 相对路径数组

### 配置工作流

```bash
# 第一次 init：自动扫描发现目录，生成骨架
api-gen init
# → includes: ["utils"]，同时发现 constants、hooks、utils 的路径

# 手动编辑 config：加入新组
# "includes": ["utils", "hooks", "types"]
# "hooks": [],
# "types": []

# 第二次 init：空路径自动填充已发现的位置
api-gen init
# → hooks 路径自动填上，已有的 utils 路径不变
```

### 多路径示例

一个组可以有多个路径，tool 会逐个处理：

```json
{
  "exportIndex": {
    "includes": ["utils"],
    "utils": [
      "packages/contract/src/utils",
      "apps/admin/src/utils"
    ]
  }
}
```

等价于对两个目录分别执行 barrel 生成。

### 路径形式组（自动展开 / 级联 barrel）

组名本身是路径（含 `/` 或以 `.` 开头），比如 `packages/contract/src` 或 `./src`。**空数组**时会自动递归展开，不用先跑 `sync` 填清单：

```jsonc
{
  "exportIndex": {
    "includes": ["packages/contract/src"]
    // 不用写 "packages/contract/src": [...] —— barrel 自动扫描
  }
}
```

**自动展开规则**（与 `sync` 共享同一份 `scanPathGroupChildren`）：

- 递归遍历组根下所有有 `.ts` 内容的子目录（任意深度）→ 每个子目录都生成 `index.ts`
- 组根的散 `.ts` 文件 → 直接进组根 `index.ts`
- 深层散文件 → 归所属子目录的 barrel 管（不上升到组根）
- SKIP_DIRS 黑名单全程生效

**级联 barrel**：每个子目录的 `index.ts` 不只聚合自己的散文件，还 re-export 直接子目录的 barrel：

```
src/index.ts                  ← 父级：散文件 + 一级子目录
src/utils/index.ts            ← 中间层：散文件 + ./nested 转发
src/utils/nested/index.ts     ← 叶层：deep 等
```

这样 `import { x } from "@/contract"` / `from "@/contract/utils"` / `from "@/contract/utils/nested"` 三种深度都能用。

显式给数组时（比如你已经手工维护了子项清单）就尊重你的清单，不再自动展开。

```bash
# 扫描所有组，生成 barrel
api-gen barrel

# 只处理某个组
api-gen barrel --group utils

# 预览模式，不写入文件
api-gen barrel --dry-run
```

### 排除路径（`!` 前缀）

在某个组的路径数组里以 `!` 开头的项会被**忽略**：

```json
{
  "exportIndex": {
    "includes": ["utils"],
    "utils": [
      "packages/contract/src/utils",
      "!packages/contract/src/utils/internal"
    ]
  }
}
```

- `packages/contract/src/utils` 正常扫描
- `packages/contract/src/utils/internal` 被排除（不进入子目录扫描，不生成 `index.ts`，父级 barrel 也不引用它）
- 运行 barrel 时会在日志里提示 `已排除（配置忽略）：packages/contract/src/utils/internal`
- 路径形式组里 `!` 同样生效：`!packages/contract/src/drizzle` 会排除该子目录（连同其后代）

**典型场景：**

- 内部实现细节目录不希望对外导出（`internal/`、`__tests__/`）
- 临时调试 / 实验目录暂时不让进 barrel
- 路径形式组里关掉某个子目录（如 `./src/_internal`）

如果整组路径全是 `!` 项（比如 `utils: ["!foo"]`），barrel 会打印警告并跳过该组，不报错。

### 3. 工作流

1. 在 `pagination/page.ts` 中新增/删除/修改导出
2. 运行 `api-gen barrel`
3. CLI 自动更新：
   - `utils/pagination/index.ts`（子模块 barrel）
   - `utils/index.ts`（组级 barrel，级联模式还会 re-export 子目录 barrel）
   - 路径形式组：`src/index.ts`（组级）+ 每层子目录自己的 `index.ts`
4. 提交变更

## 生成规则

### 子模块 index（如 `utils/pagination/index.ts`）

```
扫描 pagination/ 下的 .ts 文件（跳过 index.ts / *.d.ts / *.test.ts）
  → OXc 提取每个文件的 export 定义
  → 拆分值导出 / 类型导出
  → 生成 per-file import + consolidated export
```

输出示例：

```ts
// Auto-generated by `api-gen barrel` — do not edit manually.

import { calcPage, buildPaginationQuery } from "./page";
import type { PageOpt, PaginationInput } from "./page";

export { calcPage, buildPaginationQuery };
export type { PageOpt, PaginationInput };
```

### 组级 index（如 `utils/index.ts`）

```
扫描 utils/ 下的一级子目录（pagination / sort / search）
  → 读取各子目录 index.ts 的导出集合
  → 汇总所有值/类型导出，按子目录分组 import
```

输出示例：

```ts
// Auto-generated by `api-gen barrel` — do not edit manually.

import { calcPage, buildPaginationQuery } from "./pagination";
import type { PageOpt, PaginationInput } from "./pagination";

export { calcPage, buildPaginationQuery, sortBuilder, createSearchFilter };
export type { PageOpt, PaginationInput, SortRule, SearchCondition };
```

## 安全机制

| 场景 | 行为 |
|------|------|
| `index.ts` 不存在 | 创建 |
| `index.ts` 存在且带自动标记 | 覆盖 |
| `index.ts` 存在但无标记 | **跳过**，warn 提示 |
| 新内容与旧内容相同 | 不写入 |
| `--dry-run` | 预览不落盘 |

## 叶子文件编写规范

```ts
// page.ts  ← 叶子文件

// 函数用 export function
export function calcPage(page: number, limit: number) { ... }

// 常量用 export const
export const DEFAULT_PAGE = 1;

// 类型用 export type
export type PageOpt = { page?: number; limit?: number; };

// 接口用 export interface
export interface PaginationParams { page?: number; limit?: number; }

// ❌ 禁止
export default calcPage;
export * from "./helpers";
```

## 叶子文件导出检测规则（AST 级别）

| 源码 | 导出类型 |
|------|---------|
| `export function xxx` | value |
| `export const xxx = ...` | value |
| `export class Xxx` | value |
| `export enum Xxx` | value |
| `export type Xxx = ...` | type |
| `export interface Xxx` | type |
| `export { a, b }` | value |
| `export type { C, D }` | type |

## TSConfig 推荐配置

```json
{
  "compilerOptions": {
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "verbatimModuleSyntax": true,
    "importsNotUsedAsValues": "remove",
    "isolatedModules": true
  }
}
```

## 禁止清单

1. ❌ `export * from "xxx"` — 必须具名导出
2. ❌ `export default` — 必须是具名导出
3. ❌ index 文件内写可执行代码、副作用
4. ❌ 手动修改 CLI 生成的 index 文件
5. ❌ 同时导出 `./utils` 和 `./utils/index`
6. ❌ 把函数聚合为对象再导出
